# Plan 4: `Hr.Api` — logowanie cookie, kontrolery REST i OpenAPI — plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Zbudować projekt `Hr.Api` (ASP.NET Core): uwierzytelnianie lokalnymi kontami przez cookie z ochroną antyforgery, cienkie kontrolery REST nad serwisami z `Hr.Core` (urlopy, czas pracy, zmiany płacowe, naliczenia, audyt), jednolity model błędów (ProblemDetails) oraz dokument OpenAPI zapisany w repozytorium. Całość sprawdzona testami integracyjnymi przez HTTP na prawdziwym SQL Server.

**Architecture:** `Hr.Api` zależy od `Hr.Core` (docelowo także od `Hr.Agent`, plan 5). Kontrolery nie zawierają logiki: mapują DTO, wołają serwisy i zamieniają `ServiceResult<T>` na odpowiedź HTTP. Tożsamość (`ICurrentUser`) pochodzi z claimów cookie, zakres danych i role egzekwują serwisy. Start aplikacji migruje bazę i opcjonalnie zasila ją kontami demo.

**Tech Stack:** .NET 9, ASP.NET Core (kontrolery), ASP.NET Core Identity (cookie), `Microsoft.AspNetCore.OpenApi`, `Microsoft.AspNetCore.Mvc.Testing`, xUnit, Testcontainers.MsSql.

**Spec:** `docs/arc42/README.md` (sekcje 3.5, 5.2, 8.1, 8.5, 9: ADR-06, 10, 16, 24). Poprzednie plany (zmergowane): plan 1 (silnik), plan 2 (dane), plan 3 (serwisy). Kolejne: Agent (plan 5), Angular (plan 6), generator danych demo, import Kodeksu pracy, Docker i E2E (plan 7).

## Global Constraints

- `net9.0`, `Nullable` włączone, ostrzeżenia jako błędy. `Hr.Api` referencjonuje wyłącznie `Hr.Core` (przez niego `Hr.Rules` jest widoczny tranzytywnie, ale kontrolery go nie używają).
- Kontrolery są cienkie: bez reguł biznesowych, bez dostępu do `HrDbContext` (wyjątek: bootstrap w `Program.cs`). Encje nie opuszczają API, odpowiedzi to DTO (brak pól `PasswordHash`, `MonthlySalary` poza naliczeniami i zmianami płacowymi).
- Trasy pod prefiksem `/api`, JSON `camelCase`, daty jako `DateOnly` (`yyyy-MM-dd`), czasy wpisów jako lokalny `DateTime` bez strefy.
- Mapowanie błędów serwisów (ADR-24): `NotFound` → 404, `Forbidden` → 403, `Validation` → 422, `Conflict` → 409; ciało to `ProblemDetails` z rozszerzeniami `code` i (gdy jest) `ruleId`. Brak uwierzytelnienia → 401 (nigdy przekierowanie), brak ważnego tokenu antyforgery → 400.
- Cookie sesyjne: `HttpOnly`, `SameSite=Strict`, wygasanie przesuwane 8 h. Token antyforgery w ciasteczku `XSRF-TOKEN` (czytelnym dla JS) i nagłówku `X-XSRF-TOKEN`, walidowany globalnie dla metod innych niż GET, HEAD i OPTIONS.
- Blokada konta po 5 nieudanych logowaniach zwraca 423; zły login i złe hasło dają identyczną odpowiedź 401 (bez ujawniania istnienia konta).
- Sekrety i connection string tylko z konfiguracji (`ConnectionStrings:Hr`, zmienne środowiskowe), nie z repozytorium. Zasilanie kontami demo włącza `Hr:SeedDemoData=true` (domyślnie `false`).
- Zegar tylko przez `IClock`; w testach `FakeClock` (2026-10-16 12:00 UTC).
- Testy integracyjne na SQL Server w kontenerze; nazwy testów zaczynają się od `UCxx_` albo opisują kontrakt API. Komunikaty commitów po polsku, w formie rozkazującej, bez emoji.

## Review Focus

1. **Brak dostępu bez logowania:** każdy endpoint poza logowaniem, tokenem antyforgery i `health` zwraca 401 bez sesji; test wylicza endpointy z `EndpointDataSource`, więc nowy endpoint bez ochrony wywróci test (Task 2).
2. **CSRF:** żądanie `POST` z poprawną sesją, ale bez tokenu antyforgery, jest odrzucane (400), także logowanie (Task 3).
3. **Separacja przez URL:** `tomasz.lis` odpytujący bezpośrednio o zasób Anny dostaje 404 (nie 403), a pracownik próbujący wywołać operację kadrową dostaje 403 (Task 4, 6, 7).
4. **Jednolity model błędów:** reguła z silnika (np. brak salda) daje 422 z `ruleId`, konflikt 409, a żadna odpowiedź błędu nie ujawnia śladu stosu ani wyjątku (Task 2, 4).
5. **Wycieki w DTO:** odpowiedzi nie zawierają haseł, `PasswordHash`, `SecurityStamp` ani cudzych wynagrodzeń; logowanie nie ujawnia, czy konto istnieje (Task 3, 4).
