# Docker (Compose): lokalne uruchomienie systemu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `tools/docker/up.sh` stawia całość (SQL Server, Hr.Api z Angularem) w Docker Compose na `127.0.0.1:5080`; fonty są hostowane samodzielnie; README w katalogu głównym opisuje uruchomienie przy założeniu, że jest tylko Docker Engine.

**Architecture:** Jeden `Dockerfile` (web → publish → runtime, użytkownik nie-root) i `compose.yaml` (projekt `hr`: `hr-db` bez publikowanego portu, `hr-app` na loopbacku). Skrypty `tools/docker/{up,down,verify}.sh` w stylu `tools/dev/*`. Fonty z paczek npm (`@fontsource/roboto`, `material-symbols`) zamiast Google Fonts. Kod .NET się nie zmienia.

**Tech Stack:** Docker Engine 24, Compose v2.40, `node:24`, `dotnet/sdk:9.0`, `dotnet/aspnet:9.0`, SQL Server 2022, Angular 22.2.3, bash.

**Spec:** `docs/superpowers/specs/2026-10-17-docker-design.md`

## Global Constraints

- Zmieniamy tylko: `web/` (fonty), nowe pliki w katalogu głównym (`Dockerfile`, `.dockerignore`, `compose.yaml`, `README.md`), `tools/docker/`, `.env.example`, `docs/`. Backend, `tests/`, `docs/openapi`, `web/src/app/api/` i `tools/dev/*` nie są ruszane.
- Nasłuch tylko `127.0.0.1` (`ports: ["127.0.0.1:5080:8080"]`); `hr-db` bez sekcji `ports`.
- Sekrety (`HR_DB_PASSWORD`, `ANTHROPIC_API_KEY`) tylko w `.env` (`chmod 600`, tworzony z `umask 077`), nigdy w argv, logach, obrazie ani `compose.yaml`; skrypty ich nie wypisują. `.env` nie jest commitowany (jest w `.gitignore`) ani kopiowany do obrazu (`.dockerignore`).
- Nazwy: projekt Compose `hr`; kontenery `hr-db`, `hr-app`; wolumen `hr-db-data`; baza `hr`. Zasoby `tools/dev` (`hr-dev-db`, `hr-dev-db-data`, `.run/`) pozostają osobne.
- Środowisko `Production`, `Hr__SeedDemoData=true`; `ANTHROPIC_API_KEY` z `.env` (pusty = brak klucza, czat 503).
- Node w obrazie: `node:24` (zgodnie z `engines` `^24.15.0`); SDK: `mcr.microsoft.com/dotnet/sdk:9.0` (`global.json` ma `rollForward: latestFeature`).
- Komunikaty skryptów i dokumentacja po polsku; skrypty `set -euo pipefail`, działają z dowolnego katalogu, kończą się kodem ≠ 0 przy błędzie.
- Commity z `git -c user.name=99996927 -c user.email=99996927@pw.edu.pl commit`, z linią `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Weryfikacja końcowa: `cd web && npm run verify`; `dotnet build` bez ostrzeżeń; `tools/docker/up.sh` (smoke 1–15 + verify.sh) na czystym stanie.

## Review Focus

1. Pusty/brak `ANTHROPIC_API_KEY` w `.env` → aplikacja startuje, czat 503, reszta działa (Task 2, Task 3).
2. Utrata `.env` przy istniejącym wolumenie → `up.sh` wykrywa niezgodne hasło SA i podaje `down.sh --reset`, zamiast zapętlić się lub zawisnąć (Task 3).
3. Port 5080 zajęty przez `tools/dev/run.sh` (lub inny program) → `up.sh` odmawia z czytelnym komunikatem i niczego nie psuje (Task 3).
4. Polskie znaki na ekranach (ą, ę, ł, ż) w nowych fontach: podzbiór `latin-ext` załadowany (Task 1).
5. Ikony renderują się z lokalnego pliku (nie jako tekst ligatury) po usunięciu CDN (Task 1, ręcznie przez właściciela).
6. Ponowne `up.sh` na działającym systemie jest idempotentne (nie dubluje danych demo, nie niszczy wolumenu) (Task 3).
